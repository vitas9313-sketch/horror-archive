# HORROR ARCHIVE — AI 專案開發規則

## 1. 專案目的與對象
本專案是繁體中文「私人恐怖電影檔案館」，用固定的內容格式介紹作者喜歡的恐怖電影。核心標語：「恐怖的不一定是電影，也可能是我們踩到的雷。」未來要能只新增一筆資料，就產生風格一致的首頁卡片及獨立介紹頁。網站是個人、非商業作品。

## 2. 技術與檔案結構
- `index.html`：首頁、網站標語與電影清單容器。
- `movie.html`：共用的單片介紹範本；以 `?id=電影id` 顯示內容，不複製多份 HTML。
- `movies.js`：`window.MOVIES` 陣列；**所有電影資料的唯一維護位置**。
- `site.js`：讀取資料並渲染卡片、詳細頁；處理找不到 ID 的情況。
- `style.css`：所有頁面的共同樣式及響應式版面。
- `README.md`：使用、部署及新增內容方式。
- `AGENTS.md`：本開發規範。
使用原生 HTML/CSS/JavaScript；不要求建置工具、資料庫、框架或付費服務；可直接用 GitHub Pages 部署。可選用 Google Fonts，字型失效時須可回退至系統字型。請保留既有相對路徑，避免破壞 GitHub Pages 子路徑。

## 3. 視覺、語言與版型
- 高級感、精品影展目錄式的暗黑電影誌：碳黑底色、象牙白字、少量深酒紅、細分隔線、寬鬆留白。避免剪貼風、滿版貼紙、太多徽章及過度血腥效果。
- 全站使用繁體中文。目前版面在桌面採多欄卡片、手機採單欄；這只是現有實作，不是永久限制。首頁與 `movie.html` 應維持一致的視覺語言及導覽。
- `assets/` 僅使用針對專案新製作的 AI 原創電影氛圍意象圖或其他有合法授權的圖。不得複製電影劇照、官方海報、明星肖像、片名標準字或指定模仿特定創作者風格；每張圖片都須寫明「非官方意象」。
- 所有 CSS 放在 `style.css`，不要在 HTML 放大量行內樣式。

## 4. 新增電影資料格式
所有資料僅在 `movies.js` 的 `window.MOVIES` 維護，每部電影包含：
- `id`：英文小寫和連字號組成的唯一字串，不能與既有 ID 重複；`title`、`originalTitle`、`year`：可查證的基本資料。
- `director`、`runtime`：核實後填寫導演及片長；`genre`：1–3 個類型；`category`：供首頁篩選使用的單一分類。
- `image`：`assets/xxx.webp` 相對路徑；`tagline`：本站自行撰寫的一句引言。
- `synopsis`：約 100–220 字，具體包含人物、處境、衝突、懸念，但不揭露關鍵轉折或結局；`setting`、`fear`、`themes`、`highlights`：場景、恐懼來源、主題字詞、三個觀影看點。
- `metrics`：`scare`（突發驚嚇／明確威脅）、`gore`（暴力血腥呈現）、`pressure`（長時間緊繃和不安）、`pace`（劇情推進速度），各 1–5；**這是本站編輯性觀影指引，不是爛番茄指標、統計數據，也不可冒稱作者本人打分**。逐片評估時參照實際作品內容，不確定時不要填假數字，應標記待確認。
- `rt`：`critics`（影評正面比例）、`audience`（觀眾正面比例）、`url`（對應電影 Rotten Tomatoes 官方網址）、`checked`（YYYY-MM-DD 查詢日期）。僅在親自核對對應年份、電影版本及官方頁面後更新；不得憑空填值。百分比**不是平均星等**，以來源頁現有數字為準，數值可能變動。
- `sourceLabel`、`sourceUrl`：故事內容及基本資料的可信來源；不得將編寫的劇情摘要偽裝為官方原文。

## 5. AI 新增電影的固定流程
1. 先讀本文件、`movies.js`、`site.js`、`style.css`，確認現有欄位與設計，勿直接重寫整站。
2. 核實中文片名、原文片名、上映年份、導演、片長、Rotten Tomatoes 數值及基本劇情，保留可公開檢查的資料來源。不能查證時明確標示待確認，不得捏造。
3. 在 `movies.js` **新增一個**符合格式的物件。不得修改既有電影內容或 ID，除非作者明確要求。
4. 撰寫簡短、不劇透的簡介及 3 個具體看點；不要假稱作者已給出評分或心得；恐怖指標須符合定義並標為編輯性估計。
5. 使用既有 `movie.html` 範本呈現；需要圖片時建立新的原創氛圍圖，保持精品影展目錄風格，圖片及其檔名須加入 `assets/`。
6. 檢查首頁是否多出一張卡片、總片數是否更新、點擊卡片是否正確開啟 `movie.html?id=...`、詳細頁返回鍵與來源連結是否正常。
7. 在手機與桌面尺寸檢查文字、排版及可點擊區域；確認沒有 JavaScript 錯誤、破圖或未授權素材。
8. 在回覆中列出修改過的檔案、驗證結果及待作者補充事項。

## 6. 修改限制與內容誠信
- 不刪除、重新命名或覆蓋既有電影；變更資料結構必須同步更新所有使用該資料的程式與本文件。
- 網頁內容應明確區分「可查證資料」、「編輯整理的看點」與「來源日期明確的爛番茄評價」。
- 網站與專案文件不得包含 Notion 資料庫入口或聲稱同步外部電影資料庫。
- 不抄襲第三方影評、完整劇情介紹或受版權保護的圖片；請以自己的話簡介並附來源。
- 不加入不必要的追蹤、登入、API 金鑰或個人資料蒐集。

## 7. 完成定義
新增電影後，`movies.js` 是唯一新增資料處；首頁能顯示新卡片、詳細頁可使用唯一 ID 正常開啟，既有電影全部仍正常；手機版可閱讀，來源可查，沒有冒充作者意見的文字或未核實評分。上述條件全部通過才算完成。

## 8. AI 擴充與發布方式
- 公開網站僅供瀏覽電影，不提供新增電影表單或管理入口。
- 作者在具備專案存取權的 Codex 等開發工具中提出新增需求。AI 應先閱讀本文件，依第 5 節的流程修改程式與原創素材。
- 修改完成後由作者審核、提交與推送至 GitHub；GitHub Pages 部署成功後公開網站才會更新。
- 不得將 `AGENTS.md` 說成在網站上會自動執行的服務。純靜態網頁不會直接呼叫 AI 或寫入 GitHub。
